# EchoTracker — DECISIONS

<!-- Append-only. Формат фиксирован. -->

## 2026-09-08: Публичный репозиторий-шаблон, копия на проект

**Контекст:** Нужна одна доска на проект для соло-разработки: свои задачи и ожидание заказчика. Данные проектов смешиваться не должны.

**Решение:** Public-репозиторий MIT как шаблон. Каждая копия — отдельный деплой со своей SQLite и папкой файлов. project_id в базе нет.

**Альтернативы:** Один мультитенантный сервис на все проекты; готовый SaaS.

**Trade-off:** N копий обновлять вместо одной. Лечится шаблоном: код отдельно, данные и конфиг отдельно, обновление подтягиванием шаблона.

## 2026-09-08: Тонкий React без тяжёлых библиотек

**Контекст:** Долго считался тяжёлым, но последний проект переубедил. Ванила вечнее, React продуктивнее.

**Решение:** React thin: fetch + drag&drop, без гридов и форм-библиотек. На сервер уезжает только собранный dist.

**Альтернативы:** Ванила без сборки; тяжёлый стек с гридом.

**Trade-off:** Тулчейн и обновления зависимостей вместо вечного html-файла. Выигрыш — скорость разработки и перенос опыта.

## 2026-09-08: MD-производная docx сразу в v1

**Контекст:** Docx надо и читать быстро, и скармливать автоматизации.

**Решение:** Оригинал хранится как есть. Рядом md-производная клиентской связкой mammoth + turndown: просмотр и скачивание обоих. Полный WYSIWYG не делаем.

**Альтернативы:** Только скачать; свой офисный сервер; внешний вьювер.

**Trade-off:** Потери сложного форматирования в md. Выигрыш — ноль серверных зависимостей и md для поиска и автоматизации.

## 2026-09-08: Файлы в папке, уведомления Email

**Контекст:** Файлы прикладывает любой участник. Уведомления нужны без внешних сервисов.

**Решение:** Хранилище — папка рядом с базой (порт Storage, файловый адаптер). Имена на диске uuid, отдача через API с проверкой прав. Уведомления — порт Notifier, первый адаптер Email, в письмах ссылки, не вложения.

**Альтернативы:** MinIO/S3 сразу; вложения в письма; мессенджеры.

**Trade-off:** Без MinIO нет горизонтального масштаба — он и не нужен под копию на проект. Email без пушей — достаточно для соло.

## 2026-09-08: BPMN только просмотр, SVG-превью + PNG-миниатюра

**Контекст:** К карточкам прикладывают блок-схемы. Редактор не нужен — моделируют в Camunda Modeler. Огромных схем не будет.

**Решение:** Редактора нет. Производные при загрузке на клиенте: preview.svg основная, thumb.png для ленты и писем. Интерактив — ленивый чанк bpmn-js только при открытии карточки. Нет DI в xml — честная заглушка вместо пустого экрана.

**Альтернативы:** Свой офисный сервер; внешний вьювер; только растр.

**Trade-off:** bpmn-js тянет тяжёлый чанк, но грузится только по требованию. Конвертация на клиенте — без серверных зависимостей в копии.

## 2026-09-08: Жизнь в echo/ проекта под сабпатом

**Контекст:** Трекер — инструмент проекта: лежит в его репо, разворачивается рядом на том же домене.

**Решение:** Копия живёт в `echo/` проекта (скрипт adopt), отдаётся с `ECHO_BASE` (дефолт /echo/), префикс держит само приложение, Caddy проксирует без вырезания. Доки читаются живьём из `../docs` + `../README.md`, трекер их никогда не пишет. Кука сессии с Path=base.

**Альтернативы:** Отдельный поддомен на проект; мультитенантность; Caddy вырезает префикс.

**Trade-off:** Фронт обязан ходить относительными путями от базы сборки. Выигрыш — ноль рассинхрона доков и один домен с проектом.

## 2026-09-08: Бэк на TypeScript thin, без Nest

**Контекст:** Фронт уже тонкий React на TS. Нужен один язык на обе стороны вместо второго стека ради доски.

**Решение:** TS thin: минимум роутера + SQLite (смотрим встроенный node:sqlite) + одна SMTP-либа. Nest не берём. Go — запасной, если копии упрутся в RAM VPS.

**Альтернативы:** Go-бинарник; PHP; Python; Nest.

**Trade-off:** Node-процесс тяжелее Go-бинарника по RAM на копию. Выигрыш — shared-типы, одна валидация, скорость разработки на знакомом языке.

## 2026-09-08: Бэк с нулём runtime-зависимостей

**Контекст:** Копия на проект должна ставиться без зоопарка пакетов и собираться без шагов.

**Решение:** Только встроенные модули Node: http, node:sqlite, scrypt-сессии, SMTP-клиент своим кодом (прямой TLS + AUTH LOGIN). Запуск без сборки — type stripping. Единственные зависимости монорепо — фронт и typescript для проверок.

**Альтернативы:** nodemailer; better-sqlite3; bcrypt; express/hono.

**Trade-off:** Свой SMTP-клиент чинить нам самим при капризах серверов (очередь с ретраями это смягчает). Выигрыш — api без install вообще.
